# Task Lifecycle

Главный happy path для задачи.

## Flow

```text
research -> local task -> implementation -> test -> review -> docs update -> delete task -> final report
```

## Шаги

1. `Research Agent` понимает идею, проверяет контекст и предлагает следующий шаг.
2. `Task Planner Agent` создает одну задачу или список задач в `local-tasks/`, если Вика подтверждает.
3. `Implementation Agent` реализует только утвержденный scope.
4. `Test Agent` запускает минимально релевантные проверки.
5. `Review Agent` проверяет diff на баги, регрессии, архитектуру и missing verification.
6. `Documentation Agent` обновляет `project-docs/`, если появилось устойчивое знание.
7. `Orchestrator` удаляет завершенную задачу из `local-tasks/`.
8. `Orchestrator` возвращает final report.

## Когда пропускать шаги

- `local task` можно пропустить для маленькой понятной правки.
- `proposal` нужен, если есть несколько разумных решений.
- `docs update` можно пропустить, если изменение не меняет поведение, архитектуру, flow или команды.
- `delete task` нельзя пропускать, если задача завершена.

## Definition of Done

Задача готова, когда:

- scope реализован;
- проверки запущены или причина пропуска явно названа;
- review не содержит блокирующих findings;
- постоянные знания перенесены в документацию;
- локальная задача удалена;
- финальный отчет содержит риски и следующий шаг.

## Если задача заблокирована

Если задача не завершена:

- не удалять файл из `local-tasks/`;
- добавить в задачу короткий блок `Blocked`;
- указать, что нужно от Вики или внешней системы;
- не выдавать задачу как готовую.
