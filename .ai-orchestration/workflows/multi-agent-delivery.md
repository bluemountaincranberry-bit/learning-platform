# Multi-Agent Delivery Workflow

## Когда использовать

Использовать для задач, где полезно разделить работу на роли:

- сначала предложить решение;
- затем реализовать;
- затем проверить;
- затем сделать review;
- затем вернуть Вике итог.

Если задача маленькая и локальная, главный агент может пройти workflow без
реальных sub-agents, как последовательные роли.

Если задача начинается как идея, новая фича или архитектурное направление,
сначала использовать `research-to-delivery.md`.

## Шаги

1. Orchestrator читает профили и задачу.
2. Orchestrator проверяет Gate 1: задача понятна?
3. Если решение неочевидно, Solution Designer готовит proposal.
4. Orchestrator возвращает proposal Вике, если нужен approval.
5. После approval Orchestrator создает implementation context packet.
6. Implementation Agent делает изменение.
7. Test Agent проверяет изменение.
8. Review Agent проверяет diff и риски.
9. Documentation Agent обновляет короткую документацию, если это нужно.
10. Orchestrator удаляет завершенную задачу из `local-tasks/`, если она была создана.
11. Orchestrator интегрирует исправления или возвращает проблему Вике.
12. Orchestrator отдает final report.

Если review находит безопасные локальные исправления, Orchestrator может
применить их и повторить нужную проверку. Если проверки или review не закрыты,
задача не считается готовой.

## Контексты

### Для Solution Designer

- задача;
- профиль Вики;
- профиль проекта;
- ограничения;
- релевантный код или документация.

### Для Implementation Agent

- утвержденный подход;
- четкий scope;
- файлы или модуль ответственности;
- что нельзя менять;
- ожидаемый результат.

### Для Test Agent

- что изменено;
- какие риски проверить;
- какие команды доступны.

### Для Review Agent

- задача;
- diff или список файлов;
- результаты проверок.

### Для Documentation Agent

- что сделано;
- какие решения приняты;
- измененные файлы;
- результаты проверок;
- локальная задача, если была создана.

## Выход workflow

Финальный ответ должен содержать:

- что сделано;
- где сделано;
- как проверено;
- обновлялась ли документация;
- удалена ли временная задача;
- что осталось риском;
- следующий шаг.
