# OpenSpec: пробное использование

OpenSpec CLI 1.13.0 подключён к Codex с базовым профилем `core`.
Спецификации пишем на русском, сохраняя структурные заголовки OpenSpec
и ключевые слова SHALL/MUST на английском.

## Начать изменение

В чате Codex:

```text
$openspec-explore Исследуй подход к <идее>.
$openspec-propose Подготовь предложение для <изменения>.
```

После проверки предложения, спецификаций, дизайна и задач:

```text
$openspec-apply-change <имя-изменения>
```

Для уточнения артефактов используется `$openspec-update-change`.
После реализации и проверок — `$openspec-archive-change`.
`$openspec-sync-specs` позволяет отдельно перенести изменения требований
в основные спецификации.

## Где что хранится

- `config.yaml` — контекст проекта и правила подготовки артефактов.
- `changes/<имя>/` — предложение, дизайн, спецификации и задачи изменения.
- `specs/` — актуальные спецификации принятых изменений.
- `changes/archive/` — история завершённых изменений OpenSpec.
- `../.agents/skills/openspec-*/` — сгенерированные skills Codex.

`.ai-orchestration/` остаётся основным процессом проекта. OpenSpec пробуем
на явно выбранных изменениях; существующие задачи и архитектурные документы
автоматически не переносим. Для выбранного изменения список implementation
задач ведём в его `tasks.md`, избегая второго расходящегося списка.

## Проверки и обслуживание

```bash
openspec --version
openspec list --json
openspec validate --all --strict --no-interactive
```

Пустой проект ещё не содержит спецификаций для валидации.
После обновления CLI команда `openspec update` обновляет сгенерированные skills.
Если новые skills не видны, открой новую сессию Codex в этом проекте.
