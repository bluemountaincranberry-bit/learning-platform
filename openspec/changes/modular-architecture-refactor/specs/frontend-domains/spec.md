## Purpose

Обеспечивает предсказуемое отображение серверных данных и изоляцию пользовательского состояния при развитии frontend по доменам.

## ADDED Requirements

### Requirement: Публичные границы frontend

Архитектурная проверка SHALL отклонять HTTP-вызовы из страниц, доступ к приватным частям чужого домена и бизнес-зависимости общих UI-компонентов.

#### Scenario: Нарушение границы

- **WHEN** страница импортирует внутренний API чужого домена
- **THEN** проверка выдаёт ошибку с путём и правилом

#### Scenario: Разрешённая композиция

- **WHEN** страница собирает экран из публичных domain компонентов
- **THEN** проверка принимает структуру

### Requirement: Согласованность данных

После успешной mutation затронутые представления SHALL отражать актуальное состояние; разные фильтры MUST NOT смешивать результаты.

#### Scenario: Изменение записи

- **WHEN** пользователь сохраняет запись и открывает её список
- **THEN** список обновляется или явно показывает процесс обновления

#### Scenario: Смена фильтра

- **WHEN** завершается старый запрос после изменения фильтров
- **THEN** старые данные не выдаются за результат новых фильтров

### Requirement: Изоляция пользователя

При logout или смене аккаунта приложение SHALL исключать отображение private data предыдущего пользователя, включая поздние ответы.

#### Scenario: Поздний ответ

- **WHEN** запрос первого пользователя завершается после входа второго
- **THEN** данные первого не отображаются и не попадают в активное пользовательское состояние

### Requirement: Единые UI состояния

Повторяемые элементы SHALL поддерживать понятные loading/error/empty/retry состояния и доступное управление клавиатурой.

#### Scenario: Ошибка загрузки

- **WHEN** запрос экрана завершается ошибкой
- **THEN** видна ошибка и доступное действие повтора без потери необходимого draft

#### Scenario: Диалог

- **WHEN** пользователь открывает и закрывает общий диалог клавиатурой
- **THEN** focus управляется предсказуемо и возвращается к инициатору
