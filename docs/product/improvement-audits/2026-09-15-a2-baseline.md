# A2 learner baseline audit — 2026-09-15

## Purpose

Check whether a new A2 learner can understand the product path from first entry to content-based learning, review and AI tutor support. This is a baseline audit, not a claim that the product improves language outcomes.

## Test persona and evidence

- Persona: new learner, A2 English, wants to understand short YouTube videos, has about 20 minutes.
- Browser: Codex in-app browser; initial viewport was desktop-sized. A second browser navigation was blocked by the Codex usage-limit review, so mobile and full journey remain untested.
- App: local Docker stack, web service on `http://localhost:8088`, revision `d120ffd2b6324a4b02be2443d6ed12cf44bb04`.
- Browser evidence: home shell and registration screen were visibly inspected. No account was created and no data was changed.
- Code evidence: Vue routes/pages, Laravel module routes, AI fixtures and evaluator were inspected.

## What already works

- Guest shell exposes Dashboard, Catalog, Grammar, Practice, My words, My grammar, My lessons, Progress, AI chat and Settings.
- Registration has a short four-step onboarding flow: welcome, level, native language and daily goal. All steps can be skipped and preferences can be changed later.
- Catalog and content detail routes are guest-readable; learning state, practice, tutor and source submission are protected by authentication.
- Existing product architecture already models content, lexemes, learning flow, SRS, progress and AI as separate modules.
- Existing AI tests cover access boundaries, ownership, streaming, quiz output, empty data and handoff wiring.

## Findings

### A2-UI-001 — first entry has a confusing Create account path

- Status: observed in browser.
- Evidence: On `/`, the shell button `Create account` navigated to `/login?redirect=/dashboard`; the login page then offered `Create one` to reach `/register`.
- Impact: high for activation; a new learner can reasonably expect the primary call to action to start registration.
- Confidence: high. Owner: User / SPA shell.
- Proposed change: send the shell Create account action directly to the register route, preserving the login route’s Create one link.
- Acceptance: guest click on Create account reaches `/register` in one navigation; Login still reaches `/login`; no redirect query is lost for protected routes.

### A2-LEARN-001 — the first learning goal is not yet connected to a guided first session

- Status: code-based hypothesis.
- Evidence: onboarding collects level and daily goal, but no evidence yet shows that an A2 learner receives a recommended short content item, a bounded first activity, or an explanation of why that item was selected.
- Impact: high; “what should I do now?” is the key first-session question.
- Confidence: medium until the full authenticated flow is walked. Owner: Learning / AI / Content.
- Proposed change: define one A2 first-session contract: choose one suitable content item, show expected time and learning goal, expose a short pre-study vocabulary set, then launch one activity.
- Acceptance: an A2 learner with empty history sees one clear next action, content difficulty rationale, session length, and a completion path to review.

### A2-LEARN-002 — practice quality needs a retrieval and feedback contract

- Status: code-based finding from AI and learning flow inspection.
- Evidence: Adaptive flow models encounter → recognition → recall → production → listening → speaking. The AI quiz tool can return an empty result when the review queue is empty. The current tutor and grammar prompts do not define a consistent attempt → hint → retry → answer policy.
- Impact: high; immediate answer disclosure can turn practice into recognition instead of recall.
- Confidence: high for missing contract; no live response failure observed. Owner: Learning / SRS / AI.
- Proposed change: specify activity-level feedback states and a no-history fallback that starts with a small contextual recognition task, then recall and optional production.
- Acceptance: A2 empty-history session has a usable activity; hint gives a clue without the answer; retry gives targeted feedback; explicit solution request gives the answer and explanation; outcomes feed progress/SRS once.

### A2-AI-001 — current AI eval can pass without proving a useful final answer

- Status: code finding.
- Evidence: `AiEvalCommand.php:172` and `:188` rely on expected tool behavior while the final answer is not a required pass condition; evaluator exhaustion is not treated as failure.
- Impact: high; routing success can be mistaken for tutoring quality.
- Confidence: high. Owner: AI.
- Proposed change: fail on exhaustion, missing final answers, failed required tools and contradictions with tool results; add independently authored pass/fail examples.
- Acceptance: a case with the expected tool call but no useful answer fails; a grounded A2 answer passes only when correctness, clarity and next step criteria pass.

### A2-AI-002 — evaluated prompt may differ from production prompt

- Status: code finding.
- Evidence: evaluator constructs a static blueprint at `src/app/Console/Commands/AiEvalCommand.php:139`; production resolves registry overrides in `src/app/Modules/Ai/AiServiceProvider.php:190` and replacement logic at `:254`.
- Impact: medium-high; results may not describe the tutor users receive.
- Confidence: high. Owner: AI.
- Proposed change: evaluate the same resolved prompt as production and record prompt hash/version, model and dataset version.
- Acceptance: one test proves a published override reaches the evaluated tutor; report shows per-case results and versions.

### A2-AI-003 — new learner level and empty review state are underspecified

- Status: code finding.
- Evidence: `GetUserLevelTool.php:56` returns null for a new learner and otherwise infers from frequent vocabulary; `GenerateQuizTool.php:68` returns empty output when the review queue is empty; `StudentTutorAgentService.php:254` has no explicit A2 cold-start contract.
- Impact: high; the learner may be left without a sensible starting activity or may receive an overconfident level assessment.
- Confidence: high. Owner: AI / Learning.
- Proposed change: treat declared A2 as a preference/starting level, acknowledge missing evidence, and provide a small first activity independent of existing review cards.
- Acceptance: no-history A2 test case returns a concrete activity and does not claim that sparse vocabulary data proves proficiency.

### A2-UI-002 — full mobile and desktop responsive behavior is unverified

- Status: untested.
- Evidence: only the initial desktop-sized browser state was inspected; browser continuation was blocked by the Codex usage-limit review.
- Impact: high; learning cards, transcript controls and bottom actions are especially sensitive to small screens.
- Confidence: high that coverage is missing. Owner: SPA.
- Proposed change: run webapp-testing and impeccable audit at representative mobile and desktop viewports; capture screenshots and browser errors.
- Acceptance: baseline screenshots and findings exist for onboarding, catalog detail, study, repetitions and tutor at mobile and desktop sizes.

## Research comparison

| Product area | Current implementation | Evidence | Comparison and implication |
|---|---|---|---|
| Repetition | Project has SRS cards, due state, confidence dimensions and adaptive activity selection. | [Carpenter, Pan & Butler, 2022](https://doi.org/10.1038/s44159-022-00089-1) reviews spacing and retrieval practice. | Direction is aligned, but the audit must check whether the actual activity requires retrieval and whether spacing is adapted to performance rather than presented as a magic fixed schedule. |
| L2 vocabulary spacing | Project has configurable learning flow and SRS intervals. | [System, 2023 L2 vocabulary spacing study](https://doi.org/10.1016/j.system.2023.103049) used 67 Chinese university students and found results varied by receptive/productive knowledge and schedule. | Do not hard-code a universal interval from one study. Compare current interval rules against several studies and measure recall by skill dimension. |
| Practice format | Project contains flashcard-like, transcript, dictation, shadowing, speaking and context practice surfaces. | [Kim et al., 2023](https://doi.org/10.1111/modl.12879) studied 150 Korean L2 English learners across flashcard/fill-in-the-blank and massed/spaced conditions. | The product has the right range of modes in theory. The next audit must verify sequencing, feedback and whether practice transfers beyond recognition. |
| A2 target | Onboarding allows CEFR level selection and content has difficulty metadata. | [Council of Europe CEFR descriptors](https://www.coe.int/en/web/common-european-framework-reference-languages/cefr-descriptors) provide level-oriented communicative descriptors. | Use A2 descriptors to write acceptance examples for listening, reading, interaction and production; do not use A2 as a single global score. |

Research limits: these sources do not establish one best schedule for every learner or prove that this application improves outcomes. The studies differ in population, language, task and retention interval. A formal systematic review would require the additional literature-review search workflow and its dependencies.
